# UOS Kernel: 资源 + 数字孪生 + 世界模型 统一架构

> 分支: `agentic-redesign` (基于 `resource-space`)
> 日期: 2026-05-06

## 1. 核心定位

UOS Kernel 是**人机物统一资源操作系统内核**，为上层应用和 Agent 提供：
- 资源的统一抽象与访问
- 资源的数字孪生（状态历史）
- 资源间的拓扑关系
- Agent 的世界模型基座

## 2. 资源统一模型

所有资源（不论人/机/物）共享同一套抽象：

```
Resource {
    ID          string              // 全局唯一标识
    Type        ResourceType        // 物理/人力/信息
    Attributes  map[string]any      // 静态属性
    State       map[string]any      // 当前状态快照
    Capacities  []Capacity          // 该资源能做什么
    Twin        DigitalTwin         // 状态历史（内建）
    Topology    []Relation          // 与其他资源的关系
}
```

### 三类资源的实例化

| 类别 | ResourceID 示例 | Capacities | 状态示例 |
|------|-----------------|------------|----------|
| 物理 | `dev://40150-十图堰1-FTU-MG` | 遥测、遥信、遥控、重启 | online/offline, 通信方式, 固件版本 |
| 人力 | `person://周留康` | 接单、消缺、验收 | 在岗/离岗, 当前负载, 位置 |
| 信息 | `ticket://2026020108564900` | 流转、关联、归档 | 待接单/消缺中/已归档 |

## 3. 数字孪生 = 内建的状态历史

孪生不是某类资源的特殊 Capacity，而是 **Kernel 为所有资源内建的能力**（类比 OS 文件系统自带 mtime/版本）。

```
DigitalTwin {
    ResourceID  string
    Timeline    []StateEvent        // 有序状态变化序列
    Snapshot    map[string]any      // 当前状态（= Timeline 末端的累积）
}

StateEvent {
    Timestamp   time.Time
    Field       string              // 变化的字段
    OldValue    any
    NewValue    any
    Cause       string              // 引起变化的原因（告警/操作/...）
    Actor       string              // 谁触发的（人/系统/规则）
}
```

## 4. 世界模型 = 孪生集合 + 拓扑

对 Agent 而言，"世界"就是：

```
WorldModel {
    Resources   map[ResourceID]*DigitalTwin  // 所有资源的孪生
    Topology    Graph                         // 资源间关系图
    Now         time.Time                     // 当前时间点
}
```

Agent 的认知循环：

```
loop {
    // 感知: 从世界模型中读取状态变化
    events = WorldModel.Query(since=lastCheck, filter=...)

    // 推理: 基于历史轨迹 + 拓扑关系做判断
    //   - 这台设备第3次掉线 → 应更换而非重启
    //   - 同馈线5台同时掉 → 上游光缆问题
    //   - 负责人2小时未响应 → 可能不在岗，需转派
    plan = reason(events, WorldModel)

    // 执行: 通过 ROSIX 操作资源，更新世界模型
    for action in plan {
        ROSIX.RCtl(action.target, action.cmd, action.args)
    }
}
```

## 5. ROSIX 接口扩展

在原有 Open/Close/Read/Write/RCtl 基础上，新增：

| 接口 | 语义 | 说明 |
|------|------|------|
| `History(fd, since, until)` | 读取状态变化历史 | 查询孪生时间线 |
| `Watch(fd, filter)` | 订阅状态变化事件 | 实时感知（Agent 用） |
| `Relate(fd1, fd2, relType)` | 建立资源间关系 | 动态绑定（如工单↔人） |
| `Traverse(fd, direction, relType)` | 沿拓扑遍历 | 查上下游关联资源 |

## 7. 设计原则

1. **孪生是 Kernel 内建的**，不是应用自己维护的。任何对资源的操作自动留痕到 Twin。
2. **历史不可变**。Twin 的 Timeline 只追加，不修改。
3. **当前状态是历史的投影**。Snapshot = fold(Timeline)，不独立存储。
4. **拓扑是一等公民**。关系和资源同等重要，不是附属元数据。
5. **Agent 看到的世界模型 = Kernel 暴露的 Twin + Topology**。Agent 不需要自己建模。

## 8. 技术栈分层策略

类比 Linux：内核用 C，应用随便什么语言，中间通过 syscall 隔离。
UOS 同理：**Kernel 用 Go，Agent 用 Python，中间通过 ROSIX API 隔离**。

```
Go Kernel 进程                      Python Agent 进程
┌────────────────────┐             ┌─────────────────────┐
│ 资源 / 孪生 / 拓扑  │             │ Claude SDK / LLM     │
│ ROSIX 实现          │             │ 策略逻辑 / Prompt    │
│         ↕          │ gRPC/HTTP   │         ↕           │
│ ROSIX API Server   │ ←─────────→ │ ROSIX Client SDK    │
└────────────────────┘             └─────────────────────┘
```

**为什么这样分**：
- Go 擅长：类型安全、并发、长期运行的基础设施
- Python 擅长：LLM SDK 生态、快速迭代 prompt/策略、数据分析
- 网络边界：隔离演进速度不同的两层，也让 Agent 可以用任意语言编写

**ROSIX API 设计原则**：
- 协议无关：先 HTTP/JSON（开发快），后续可换 gRPC（性能）
- 语义等价：API endpoint 与 Go 侧 ROSIX interface 一一对应
- 无状态 FD：网络场景下 FD 改为 session-scoped token，Kernel 侧管理生命周期

**各语言 Client SDK 的角色**（类比 libc）：
- 封装网络调用细节
- 提供语言原生的类型和错误处理
- Python client 最先实现，后续按需加 Go/TS client
